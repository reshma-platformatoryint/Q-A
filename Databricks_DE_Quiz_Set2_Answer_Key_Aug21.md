# Answer Key — Databricks Data Engineer Practice Quiz — Set 2

| # | Correct Answer | Short Rationale |
|---|---|---|
| Q1 | **D** — `.option("cloudFiles.schemaLocation", "/path/to/checkpoint")` | Setting `cloudFiles.schemaLocation` persists the inferred schema to that path, so subsequent runs read the stored schema instead of re-sampling files, while Auto Loader still tracks/evolves the schema over time. |
| Q2 | **A** — Use a foreach task to run the same validation notebook for each table in parallel, passing the table name as a parameter | A `for each` task loops a single parameterized notebook task over a list of inputs (the tables) and can run them in parallel, replacing 15 duplicated sequential tasks with one reusable, scalable task. |
| Q3 | **B** — `EXCEPT` with `daily_activities@v{current_version-1}` | `EXCEPT` correctly returns rows in the current version not present in the prior version (the true "difference"); `@v{version}` is valid Delta Lake time-travel syntax. The other options use invalid `AS VERSION =` syntax and/or the wrong set operator (MINUS syntax invalid in Spark SQL, INTERSECT/UNION don't represent "difference"). |
| Q4 | **D** — `MERGE INTO orders_silver ... WHEN NOT MATCHED THEN INSERT *` | `dropDuplicates` with a watermark only dedupes within the in-memory state window, so duplicates arriving after the watermark expires slip through. Running a `MERGE INTO` against the full target table inside `foreachBatch` checks against *all* previously written data, catching late duplicates that watermark-based state has already dropped. |
| Q5 | **D** — The VACUUM command was run on the orders table | A SHALLOW CLONE table only copies metadata and references the original table's data files — it does not copy the actual data. If `VACUUM` is run on the source `orders` table, it can physically delete data files still referenced by `orders_backup`, causing "file not found" errors when querying the clone. |
| Q6 | **B** — ON VIOLATION FAIL UPDATE | In Lakeflow/DLT SQL expectations, `ON VIOLATION FAIL UPDATE` immediately stops pipeline execution when a record violates the constraint. Plain `EXPECT` (no clause) only warns, and `ON VIOLATION DROP ROW` discards bad records without failing. "ON VIOLATION STOP" and "ON VIOLATION FAIL PIPELINE" are not valid clauses. |
| Q7 | **D** — `trigger(processingTime="2 minutes")` | `trigger(processingTime=...)` is the correct API to run micro-batches on a fixed interval. The other options either use an invalid signature (`trigger("2 minutes")`, `trigger(once=...)`) or call a non-existent standalone `processingTime(...)` function. |
| Q8 | **B** — addNewColumns | `addNewColumns` (the default evolution mode) fails the current stream run when a new column is detected, but updates the schema at `cloudFiles.schemaLocation` so the next run picks up the new column and succeeds, while existing columns keep their inferred types. |
| Q9 | **B** — Auto Loader monitors a source location, in which files accumulate, to identify and ingest only new arriving files with each command run, skipping files already ingested. | This is the core definition of Auto Loader (incremental, exactly-once file discovery and ingestion). The other options describe CLONE, APPLY CHANGES/CDC, and Delta Lake's ACID/storage-layer capabilities respectively — not Auto Loader. |
